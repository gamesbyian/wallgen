# ROYGBIV: active product roadmap and work queue

## Warm film halation shipped as isolated treatment (PR pending, 2026-10-22)

Light → Photo → Inspired look adds **Warm film halation**. A 600×1300-or-smaller sampling field extracts luminance-selected bright areas from the *original completed frame*, blurs them with bounded separable passes, and spills a red-orange glow only into neighboring darker pixels. This is a real spatial finishing operation, not the original per-pixel tone/grain or geometry-specific object Glow. It uses one small temporary spatial mask (plus intermediate), the existing Photo renderer/export/worker path, Amount mixing, Undo, saved recipe and metadata; old presets and disabled looks remain unchanged. Only this new preset serializes an explicit `parameters.halation`, leaving older parameter shapes stable. Focused tests cover seed determinism, edge localization, hue, neutral output and archived parameter shape. No additional editor destination or CI workflow.

**Still open:** visual artistic sample approval, physically accurate linear-light scattering and multi-radius diffusion, 19.8MP Pixel performance, a dedicated fine-tuning halation slider, complex stack authoring, combined embroidery/photo judgement. This advances Film F2 **first halation** but not full photochemical simulation.


## Camera-inspired low-resolution capture preview (PR pending, 2026-10-22)

The common Photo engine now offers a **separate Low-res webcam capture** preset alongside the earlier colour-only webcam preview. This new opt-in mode samples a bounded 200-column sensor image (aspect-matched, at most 520 rows) from the final composed wallpaper, averages small source neighborhoods, shares colour information across 2×2 sensor blocks, and quantizes luminance/chroma. It then upscales the signal through the same deterministic final Photo stage; only the low-resolution temporary buffer is allocated, never another 20MP image. Original webcam colour and all prior presets keep their original rendering branches. Tests cover detail loss, stable output, alpha and zero-amount neutrality. This advances Camera D3 signal quality, **not** actual MJPEG/JPEG entropy coding, device sensor models or calibrated 480p performance. Actual phone render quality and runtime remain open.


## New Film grain-only creative look (PR pending, 2026-10-22)

Photo → Inspired look now includes **Film grain only**. Its expanded recipe is neutral for contrast, saturation, channels and vignette; only controllable seeded grain changes the authored image. A two-scale grain field adds fine emulsion speckles and subtle lower-frequency density variation anchored in authored canvas coordinates. Existing six presets retain their original code path and stored parameter values; the new effect is opt-in, works through the shared renderer/export/worker Photo finish, and adds no extra editor or CI workflow. Focused neutral-pixel, seed and multi-resolution tests cover the new mode. This advances Film F2 *grain variation only*: halation, physically meaningful density, device performance, and visual quality judgement remain unverified.


## PNG integrity gate before surgical recipe updates (PR pending, 2026-10-22)

The non-render PNG recipe updater now validates **all original PNG chunk CRCs** (including opaque IDAT, colour and descriptive metadata), IHDR dimensions/mode, palette order, IDAT contiguity and unknown critical PNG chunks before making a replacement. Output is checked again. Invalid images are refused rather than receiving a deceptively valid modernized recipe. Validation reads existing bytes, never decodes the picture, and adds no screenshot factory or required CI workflow. A formerly reused 1×1 test PNG had an **invalid IDAT CRC**; the focused migration fixture was corrected. Historical v1 and incomplete early-v2 recipe translation remain separately gated. Focused unit tests cover the new refusal modes.


## Embroidery object targeting exposed in editor (PR #482, 2026-10-22)

[#482](https://github.com/gamesbyian/wallgen/pull/482) connects the existing `surfaceTreatments.target.scope='object'` implementation to Texture → Surface → Thread. A contextual single-object picker now lists actual generated region IDs and each authored ribbon ID, including repeat bundles, and keeps missing saved IDs visible instead of silently changing targets after a scene edit. Source controls retain the same single `editor-stitches` treatment and Undo/PNG recipe path; unrelated custom treatment entries stay intact. No new top-level destinations, cloned controls, renderers, randomization lanes or CI workflows.

**Still open:** paint-scene or gallery click-to-target shortcuts, more than one simultaneous editor-owned treatment, outlines/interior stitches, artistic device review and advanced thread science. This advances E1 object selection and E4 UX without declaring full #467 acceptance.

## Stitch continuity correction: foreground crossings (PR #481, 2026-10-22)

[#481](https://github.com/gamesbyian/wallgen/pull/481) corrects the first embroidery renderer's missing thread layer on self-crossing foreground branches. Loop/drawn crossing repaint now restores the original ribbon's stitches inside the *same branch clipping mask*, with a bounded station interval and no change to baseline designs. The sampling lattice is unchanged, so optical thread spacing does not jump at intersections, and repeated crossing touch-ups do not iterate the full 2,500-station field. Focused direct tests cover deterministic lattice subsequences and geometry variants. Visual Pixel proof and physically realistic thread shading remain open. No new workflow.
