# ROYGBIV: active product roadmap and work queue

## Seven actual production Photo images viewed and inspected (2026-10-22, PR pending)

A one-time, branch-gated Chromium Actions probe **successfully generated seven real 600×1300 wallpapers**, and its artifact was downloaded and visually reviewed. The original, Slide, Muted Negative, Grain Only, Warm Halation, Smartphone HDR and Low-res Webcam show distinct actual Photo results. All seven source PNG files passed independent CRC/decoder checks and exact embedded-recipe-vs-sidecar equality checks. See [direct observed findings, measured pixel differences and two specific aesthetic follow-ups](PHOTO-PRODUCTION-RENDER-FINDINGS-2026-10-22.md). Notable nuance: halation is correctly localized but almost invisible at thumbnail scale even at strength 100, while Muted Negative lifts black to warm charcoal. Do **not** silently change saved Photo presets to correct those aesthetic questions. The one-off Actions probe was **removed** from the branch and its temporary PR #496 closed unmerged: permanent quick CI is unchanged. Pixel-native performance, multi-material compositions and physically accurate camera simulation remain open.


## Neutral Photo finishing skips export-size readback (PR pending, 2026-10-22)

`src/photo-look.js` now detects a **fully neutral normalized Photo treatment** (e.g., Grain Only at Grain 0 or Warm Halation at Halation 0 and Grain 0) before asking Canvas2D for an entire image buffer. Both the production compositor and pure in-place pixel processor skip expensive work when absolutely no tone, colour, grain, vignette or halation transform remains. The opt-in simulated low-res webcam **cannot** use this optimization because its spatial capture still changes pixels despite neutral tone settings. Existing non-neutral looks, saved recipe data and rendering math remain unchanged. Focused tests assert zero read/write calls at full 3024×6552 dimensions and unchanged active spatial-camera and grain behavior. This is a source-level performance win, **not** a measured Pixel device speedup. No new CI workflow.


## Historical PNG Restore gets truthful renderer-compatibility feedback (PR #494 merged, 2026-10-22)

The ordinary **Restore design from PNG** journey has continued to accept legacy v1/v2 recipe records through the same `normalizeRecipe` semantics; it previously said “Restored original wallpaper settings”, which implied exact source-image reconstruction despite verified historical default/renderer drift. The importer now returns the validated selected recipe and provenance in **one raw read**. The UI detects v1 dialects, fields that today's normalizer changes/synthesizes, and multi-record files, and reports that the restored artwork may differ under the current generator while asking the user to keep the source PNG. A fully current canonical PNG receives a shorter, still honest cross-version note. This is an **informational notification**, not a confirmation dialog, import rejection, automatic migration or changed Undo flow; exact-byte archival rescue and strict metadata-only migration remain separate. Focused import/notice tests and no extra CI.


## Contextual Photo halation strength without a taller tray (PR #493 merged, 2026-10-22)

The existing Light → Photo controls now expose the previously hidden **Warm Halation strength** through the *same second slider slot* occupied by Grain for every other Photo look. Selecting Warm Film Halation swaps Grain for Halation while keeping Amount alongside it, a two-control grid and no additional tool destination or vertical settings scroll. The contextual value travels through normal `photoLook.parameters.halation` normalization, Undo, exported PNG, favorites and headless/worker processing. Switching between looks restores their own preset values rather than leaking the previous effect's controls. All prior Photo presets and their original parameter serialization remain unchanged. Lean focused tests check the exact control arrangement, restoration wiring and real numeric change in warm edge pixels. Full visual/physical Pixel acceptance remains queued.


## Rescue malformed historical recipe records without parsing them (PR #492 merged, 2026-10-22)

The archival PNG rescue tool now decouples **copying original named `ROYGBIV Recipe` iTXt chunks** from `JSON.parse`. If the overall PNG container/CRC is valid but the old recipe text is malformed, uses an unsupported encoding or an unfamiliar dialect, `inspectPngRecipeArchive` detects recoverable named chunks. More → Files & sharing still refuses unsafe recipe updates but enables **Save original recipe records (exact bytes)**, with an informative report. The `png:migrate --archive` CLI writes that backup *before* attempting semantic inspection, returning a refusal status without changing the PNG. Archived record formats may be `null` if unreadable; binary length/type/text/CRC remain intact. Fixed bounds (64 records/16 MiB total/1 MiB each), intact-image validation, targeted UI and real CLI salvage tests. This advances the existing preservation queue rather than authorizing any unproven historical conversion. No new CI workflow or screenshot suites.

## Conflicting historical recipe-record preservation (PR #490 merged, 2026-10-22)

## Historical source-default archaeology (PR #488 merged, 2026-10-22)

The existing 45-revision membership ledger is supplemented by [a source-expression comparison utility](../scripts/build-recipe-format-history.mjs) and [four SHA/Blob-pinned semantic anchors](recipe-format-history/SEMANTIC-EXPRESSION-ANCHORS.json), with a [specific default/translation-gate matrix](recipe-format-history/SEMANTIC-DEFAULTS-AND-ADAPTER-GATES.md). ## Exact-byte historical recipe backup without conversion (PR #487 merged, 2026-10-22)

More → Files & sharing → Update recipe inside existing PNG now also offers **Save original recipe records (exact bytes)**, available whenever a structurally valid ROYGBIV PNG contains named recipe records, *including historical v1, unsupported dialects and otherwise unsafe-to-migrate recipes*. It writes a separate, versioned JSON dossier with each original iTXt chunk encoded byte-for-byte (including text, whitespace, duplicated historic fields, envelope, CRC, order/offset) and selected record provenance. Does not modify the PNG or active editor. The same export is available with `npm run png:migrate -- --in old.png --archive original-recipes.json --dry-run`; this CLI still exits nonzero if a requested migration is unsafe. Bounded archive memory (64 records/16 MiB chunk bytes), unchanged CRC validation. This provides concrete preservation while conservative historical translation remains gated. Tests cover refused v1, duplicate chunks, byte fidelity and UI routing. No new CI workflow.


## Warm film halation shipped as isolated treatment (PR #486 merged, 2026-10-22)

Light → Photo → Inspired look adds **Warm film halation**. A 600×1300-or-smaller sampling field extracts luminance-selected bright areas from the *original completed frame*, blurs them with bounded separable passes, and spills a red-orange glow only into neighboring darker pixels. This is a real spatial finishing operation, not the original per-pixel tone/grain or geometry-specific object Glow. It uses one small temporary spatial mask (plus intermediate), the existing Photo renderer/export/worker path, Amount mixing, Undo, saved recipe and metadata; old presets and disabled looks remain unchanged. Only this new preset serializes an explicit `parameters.halation`, leaving older parameter shapes stable. Focused tests cover seed determinism, edge localization, hue, neutral output and archived parameter shape. No additional editor destination or CI workflow.

**Still open:** visual artistic sample approval, physically accurate linear-light scattering and multi-radius diffusion, 19.8MP Pixel performance, a dedicated fine-tuning halation slider, complex stack authoring, combined embroidery/photo judgement. This advances Film F2 **first halation** but not full photochemical simulation.


## Camera-inspired low-resolution capture preview (PR pending, 2026-10-22)

The common Photo engine now offers a **separate Low-res webcam capture** preset alongside the earlier colour-only webcam preview. This new opt-in mode samples a bounded 200-column sensor image (aspect-matched, at most 520 rows) from the final composed wallpaper, averages small source neighborhoods, shares colour information across 2×2 sensor blocks, and quantizes luminance/chroma. It then upscales the signal through the same deterministic final Photo stage; only the low-resolution temporary buffer is allocated, never another 20MP image. Original webcam colour and all prior presets keep their original rendering branches. Tests cover detail loss, stable output, alpha and zero-amount neutrality. This advances Camera D3 signal quality, **not** actual MJPEG/JPEG entropy coding, device sensor models or calibrated 480p performance. Actual phone render quality and runtime remain open.


## New Film grain-only creative look (PR pending, 2026-10-22)

This advances Film F2 *grain variation only*: halation, physically meaningful density, device performance, and visual quality judgement remain unverified.


## PNG integrity gate before surgical recipe updates (PR pending, 2026-10-22)
