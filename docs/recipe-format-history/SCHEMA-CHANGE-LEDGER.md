## How to use for migration

1. Locate the PNG's envelope version and source-era fingerprint using [REGISTRY.md](REGISTRY.md), [manifest.json](manifest.json) and source-commit date range where available.
2. Compare its explicit raw recipe fields to the snapshots for that era. **Missing keys alone cannot uniquely date a recipe.** Look for defaults, enum additions, and image export provenance.
3. Check actual source diffs for every relevant revision, including unchanged-key diffs, and sample generator outputs from frozen source when possible.
4. Implement a small version-specific transformation, keeping original fields recoverable. Prove old input → new recipe properties with fixtures before enabling the Download migration button for that dialect.
5. Keep current PNG raster and non-recipe ancillary bytes untouched throughout; migrations require **both** exact image preservation and honest recipe-fidelity reporting.

**Reproduction:** `node scripts/build-recipe-format-history.mjs` in a full local Git checkout generates a comparable key history. The script uses the local Git graph and may include additional branches, so its revision count can legitimately differ from this main-history snapshot.

## Active additions after the frozen archaeology range

The pinned 45-revision source-blob ledger above remains immutable. The active editor now adds `stripeShadowPlacement`, `stripeShadowColorMode`, `stripeShadowCustomColor`, `stripeShadowInvert`, `glowPlacement`, `glowColorMode`, `glowCustomColor`, and `glowInvert` (November 2026). They are deliberately not attributed to any October source commit. Missing keys load `outer` placement, original grey-blue stripe shadow and stripe-coloured glow, with inversion disabled. The `stripeShadowStrength` default stays zero.

### Decorative edge profiles (November 15, 2026)

The path editor gained `scalloped` as a genuine `geometry` choice. This mode keeps a straight centreline and decorates real ribbon outlines, independent of the existing `loops` path geometry. Optional stripe fields are `stripeEdgeStyle` (straight/scalloped/pinked/wavy/stepped), `stripeEdgeSize`, `stripeEdgeDepth`, `stripeEdgePhase`, `stripeEdgeDirection`, `stripeEdgeSides` and `stripeEdgeAlignment`. In existing recipes, absent fields normalize to `straight`, 50, 70, 0, outward, both and aligned respectively. The `scalloped` geometry itself enables scalloped edges unless another explicit stripe edge style is selected.

Regions gained `regionEdgeStyle`, `regionEdgeSize`, `regionEdgeDepth`, `regionEdgePhase`, `regionEdgeDirection` and optional `regionEdgeOverrides` for individual stable region IDs. Absent fields normalize to straight, 50, 50, 0 and outward; the optional override list stays absent when empty. Each override is a finite, bounded profile including ID, style, size, depth, phase and direction. The existing PNG envelope/transport format is unchanged. The 45 source-pinned archaeological snapshots above must not be rewritten to claim these controls existed in 2026-10.

The painter preserves every unstyled region object and all old ribbon edge computations. When enabled, decorated region boundaries are reused for fill, clip, dividers and effects. Shared polygon edges with identical profiles use a deterministic canonical sampling order; mixed neighbouring overrides retreat inward to expose a deliberate background cut, rather than overlap. Zoom and export resolution do not change profile periods because edge stations live in design units.

### Bouncing ribbon visual correction (November 15, 2026)

The visible Path geometry choice formerly called “Scalloped ribbon” is now “Bouncing ribbon”. The serialized geometry identifier remains `scalloped` for existing PNG recipes and links. Its default outline now uses a continuous band with broad, shallow upper arches and narrower, deeper rounded drops under their joins (rather than synchronized oval-like scallops). The active Path > Geometry sliders `shapeFrequency` and `shapeDepth` control bounce frequency and bounce height; zero height yields a straight edge. Optional stripe edge phase, sides, direction and alignment still affect the bounce. Explicit `stripeEdgeStyle: "scalloped"` retains the existing edge-only/bunting/ric-rac treatments, as do region scallops. No extra recipe fields or envelope migration is required.

### Bouncing ribbon spacing and height refinement (November 16, 2026)

The initial bounce geometry reused the decorative scallop pitch (18–142 world units) and limited both amplitudes by the stripe width. On thin strokes, the extremes looked nearly identical and even minimum density had far too many tiny lobes. Bouncing ribbon now uses its own nonlinear frequency range: 360 world units per bounce at frequency 0 down to 90 at 100. Height has a nonlinear response proportional to pitch, with upper arches reaching 11.5% of pitch and lower drops 22% at maximum height, while height 0 is exactly straight. Lower drops originally spanned 70% of the period to yield broader horizontal movement. Independent stripe scallops and region edge treatments keep their original pitch, semantics and saved values.

### Continuous bouncing contours (November 16, 2026)

The lower bounce profile no longer truncates its rounded lobe at 35% of the pitch on either side, leaving 30% of the period with zero offset (a conspicuous straight shelf through the ribbon). Lower bounce displacement now follows a raised cosine over the entire period, maintaining the same pitch, peak height, and adjustable independent phase but with a continuously varying slope and no flat intervals. Its zero-displacement valley is an isolated point with a horizontal tangent, rather than a straight segment. The broad upper arch and unrelated scalloped edge treatments remain unchanged.


### Bouncing ribbon centerline correction (November 16, 2026)

This entry supersedes the three earlier November 15–16 edge-based bounce descriptions above. The serialized geometry identifier remains `scalloped` and the editor still calls it **Bouncing ribbon**, but the shape is now a single periodic **centerline**, sampled through the ordinary `pathPosition() → samplePath() → ribbonEdge()` pipeline. No special upper/lower boundary displacement is applied. The earlier `bouncingRibbonOffset()` is removed.

The dedicated `bouncingCenterline()` uses an asymmetric periodic time warp over a rounded quadratic ballistic profile. Its short rebound and long flight join with continuous first and second derivatives. The pitch remains `90 + 270 * (1 - frequency/100)^1.35` world units, preserving the broad-to-tight frequency range. Excursion scales with `(70 + 0.2 * pitch) * (height/100)^1.15`: height zero produces a straight centerline, while the height range stays useful even for thin strokes. The small pitch dependence prevents a fourfold change of visible height across the frequency range, without any stripe-thickness cap.

`stripeEdgePhase` and `stripeEdgeAlignment` shift the entire bounce trajectory; `stripeEdgePhaseB`, edge direction and edge side selection are meaningful only for **decorative edge styles**. Explicitly selecting scalloped, wavy, pinked, or stepped stripe edges now decorates the already-bouncing centerline without disabling its geometry controls. Region treatments are unchanged, as are saved recipe fields. Individuality adjusts timing across colours without deforming the two sides separately. Existing recipes using this geometry deliberately render differently because the previous appearance was incorrect.

The physical cross-section uses the same normal-offset `ribbonEdge()` computation as other paths, with `widthAt()` applied after the centerline and tangent are computed. At extreme high-frequency/high-height combinations with unusually wide stripes, normal offsets can self-intersect where the rebound curvature radius is smaller than half the thickness; this is a geometric limitation of offsets, not a hidden height clamp. No automatic width-dependent bounce reshaping is applied.

Tests: `node --test tests/bouncing-centerline.test.js tests/edge-profiles.test.js`. Generate the six visual acceptance plates via `node scripts/bouncing-centerline-plates.mjs artifacts/bouncing-centerline` and inspect the generated `index.html`. PR CI attaches the same SVG collection as an artifact. SVG visual plates use the production centerline and normal-edge samplers. The PR's opt-in `[bounce-browser]` CI lane runs `node tests/bouncing-ribbon-browser.mjs` independently of the much broader touch-control browser suite against actual Chromium Canvas2D preview and worker PNG output, verifies pixel parity and embedded recipe reimport, and uploads its raster screenshots. Reference-image resemblance remains a visual acceptance judgement rather than a claim made by unit tests.


### Bouncing ribbon tiled-arc silhouette correction (November 16, 2026, later)

This entry **supersedes the asymmetric ballistic motion** described immediately above. The owner supplied a more explicit image reference: rows of short, adjacent **rounded arches**, with a broad curved crown halfway through every repetition, steep approaches to each join, and no alternating sinusoidal hills or asymmetric bounce timing. Previously, the centreline was a smooth but pointed wave and therefore looked like softened zigzags. A mathematically correct centreline was insufficient because it was the wrong shape.

The saved geometry ID stays `scalloped` and the visible choice remains **Bouncing ribbon**. `bouncingCenterline(station,frequency,height,phase)` now constructs one archlet per `bouncingPitch(frequency)`. It uses a fourth-root circular-cap approximation: the normalised form of `(sin²(π·t) + 0.025²)^(1/4) - sqrt(0.025)`, for `t = fract(station/pitch + phase)`. This is deliberately **not** an ordinary sine wave: the quarter-power broadens the crown and steepens both sides, approximating a row of semicircular arcs. The small positive contact parameter produces smooth derivatives at the inter-arch joins instead of mathematical cusps that break normal offsets. The crown is exactly centered at half a pitch and every arch is symmetrical. This characteristic survives both thin and thick stripe constructions, although extremely wide stripes can still overlap their own normal offsets at the narrow joins.

The frequency mapping remains 360 to 90 world units per arch (slider 0 to 100). Bounce height changes the vertical *centerline* excursion via `(40 + 0.16*pitch) * (height/100)^1.15`, never based on stripe width. At height zero the centreline is straight. Phase and stripe-to-stripe alignment shift the entire arc train; decorative physical edge shapes remain independent and optional. The renderer samples this geometry at a maximum 85 stations per period, capped at 3 world units between samples, without increasing the cost of unrelated geometry.

The established normal-offset `samplePath() → widthAt() → ribbonEdge()` construction remains the sole source of both boundaries; the deleted bouncing-specific stripe edge displacement does not return. `tests/bouncing-centerline.test.js` now asserts the symmetric, round-shouldered **arc chain** contract rather than the obsolete early ballistic apex. Deterministic scene plates and the focused production Chromium / PNG worker comparison remain the acceptance evidence. The latest arc-chain visual reference is the intended shape; a valid periodic wave is not sufficient visual proof.


### Bouncing ribbon swept-union fill correction (November 16, 2026, latest)

**Rendering change, no recipe schema change.** The tiled repeating-arch centerline introduced by PR #1086 remains unchanged, including `bouncingPitch()`, `bouncingCenterline()`, height, frequency, individual phases, and normal-offset `ribbonEdge()` semantics.

The previous Bouncing ribbon fill concatenated negative and positive normal-offset boundaries into a *single closed polygon*. Although the centerline is smooth, the extremely narrow joins have a curvature radius smaller than the half-width of ordinary stripes. For example, frequency 42/height 79 has approximately **0.28 design-unit** radius at the joins. The inner offset necessarily folds back, turning the globally closed polygon into overlapping loops with nonzero winding cancellations, triangular gaps, and bow-tie contours. Subdividing the same invalid offset polygon cannot fix this.

Continuous Bouncing ribbon fills now use `src/swept-ribbon.js` through the shared `stripeFillPath()` route. Each short pair of real (possibly decorated/textured/tapered) edge cross-sections forms a consistently wound convex hull. At high curvature relative to stroke width, locally overlapping round disks seal the normal-offset fold. The entire set is filled **once as one nonzero-winding Path2D**, not alpha-composited per segment. This avoids antialiasing seams, supports opaque and translucent pigment through the existing common fill/mask pipeline, and leaves gentle-curvature edge decorations intact. Sample subdivisions are driven by angular turn; they support smooth contours but are not relied upon to repair self-intersection.

The original normal-offset contour remains available for edge-line effects and outlining, but continuous Bouncing ribbon **fills, pigment masks, glow/shadow masks, clips, preview, and worker PNG** now share the swept-union footprint. No bounce amplitude clamp, arc flattening, width reduction, or altered design controls is used. Other geometries are unaffected.

Regression evidence: `tests/bouncing-swept-ribbon.test.js` exercises the exact 42/79 join, width/height/frequency matrices, positive winding, taper, independent decorative edges and stripe phases. `tests/bouncing-ribbon-browser.mjs` checks real preview and worker parity, the seven-colour vertical black-background owner scene, and Canvas2D pixel occupancy near previously defective arch contacts. `scripts/bouncing-centerline-plates.mjs` now publishes paired **before (old globally wound polygon)** and **after (actual production union)** SVG plates; old polygon plates must no longer be interpreted as current render output. The artifact index and browser screenshots are intended for visual review along with mathematical tests.
