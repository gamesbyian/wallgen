## How to use for migration

1. Locate the PNG's envelope version and source-era fingerprint using [REGISTRY.md](REGISTRY.md), [manifest.json](manifest.json) and source-commit date range where available.
2. Compare its explicit raw recipe fields to the snapshots for that era. **Missing keys alone cannot uniquely date a recipe.** Look for defaults, enum additions, and image export provenance.
3. Check actual source diffs for every relevant revision, including unchanged-key diffs, and sample generator outputs from frozen source when possible.
4. Implement a small version-specific transformation, keeping original fields recoverable. Prove old input → new recipe properties with fixtures before enabling the Download migration button for that dialect.
5. Keep current PNG raster and non-recipe ancillary bytes untouched throughout; migrations require **both** exact image preservation and honest recipe-fidelity reporting.

**Reproduction:** `node scripts/build-recipe-format-history.mjs` in a full local Git checkout generates a comparable key history. The script uses the local Git graph and may include additional branches, so its revision count can legitimately differ from this main-history snapshot.
