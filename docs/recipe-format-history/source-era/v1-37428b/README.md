# Original PNG v1 source-era fixture

This folder pins **the exact, unmodified JavaScript Git blobs** from [initial PNG v1 introduction `37428b624e55a0d4526b992bfe6fdf4a01b5f420`](https://github.com/gamesbyian/wallgen/commit/37428b624e55a0d4526b992bfe6fdf4a01b5f420):

| --- | --- | --- |
| `src/model.js` | `37ef7d429324c65773068bd06fd3452063a981e5` | Original version-1 `normalizeRecipe`, source-era defaults, seeded scene builder |
| `src/png-metadata.js` | `37adaec2063b787713e094ee331758c04bd504c1` | Original `roygbiv-recipe-v1` serializer, exact old PNG iTXt writer |
| `src/renderer.js` | `5c12b7c505e7044db6a6ca04ddd31938ffd7f05b` | **Unmodified original painter**, available to the opt-in browser pixel-proof tool |

The copies of **all three archived source modules** are **not to be edited**. The focused `tests/historical-v1-source-era.test.js` confirms byte-for-byte Git blob hashes, runs the **actual original normalizer and original PNG exporter**, compares four independent seed/boolean/strength/layer settings in `EXPECTED-SEMANTICS.json`, and feeds those authentic v1 PNG metadata records through today's strict reader, non-destructive inspector and exact-byte archival backup. It intentionally generates tiny 1×1 PNG *containers* for test speed; the original writer still serializes its historical 3024×6552 output declaration, so these are **not** examples of 2026 source-era image pixels. Do not claim historical renderer, colour/texture defaults across all v1 revisions, or composition parity with contemporary rendering.

**Critically:** the original writer's v1 serialization and the current v2 recipe normalizer are **different software**. The tests must never call the modern serializer to manufacture an apparently historical fixture. The source-era fixture is generated by the first original v1 implementation. Conversion remains refused in both the test and the app; a narrow source-era visual/renderer golden pass and per-era adapters remain necessary.

No new CI job, browser build, package dependency, recipe import mode or migration approval was introduced. The original source snapshots live here as archival test-only code, not production modules.

## Original renderer visual fixture

The separate opt-in `scripts/review-historical-v1-render.mjs` imports **this frozen `renderer.js` and `model.js` in Chromium**, paints two original-v1 600×1300 wallpapers with *the same original seed and shadow settings except the historical shadow toggle*, then calls **this exact original `png-metadata.js` writer** to add genuine v1 iTXt. It writes the old normalized recipe, manifest (including original IDAT SHA-256), images and HTML contact sheet without modern rendering or reinterpretation.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 &
node scripts/review-historical-v1-render.mjs --out-dir artifacts/v1-shadow-golden
```

Browser/image acceptance must be recorded separately from source tests. Because the frozen v1 writer reported native **3024×6552** dimensions regardless of a preview's actual **600×1300** canvas, the metadata's `output` value can differ from the IHDR here: that is historical source fidelity, not a correct migrated output claim. The screenshot is **original first-v1 pixels**, not proof that modern ROYGBIV can reproduce them. No v1 migration is enabled.
