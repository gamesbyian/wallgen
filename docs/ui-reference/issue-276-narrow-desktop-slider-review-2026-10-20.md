# Issue #276: source-exact narrow-desktop slider verification

## Baseline and confirmed defect

The independent [156-card, two-theme live Chromium atlas](https://github.com/gamesbyian/wallgen/actions/runs/39381312821/artifacts/12246235751) caught an actual 791×892 Paths/Geometry counterexample: both Shape frequency and Shape depth had effectively **no visible draggable track** between their original increment/decrement buttons, while phone 412px had usable tracks. The related Lighting, Material and Stripe screens exhibited similar compression. Outer-row no-overflow checks alone did not detect lost slider width.

The first desktop-only CSS trial stacked existing range labels above native steppers at 791–899px. The [first independent production Chromium audit](https://github.com/gamesbyian/wallgen/actions/runs/39395509361/artifacts/12251627811) checked 1,500 real selected-tool states, 1,440 visible source range fields, both themes, 10 viewport profiles and three structures. All **228 active slider tracks at 791/850/899px were at least 72 CSS px wide**, versus near-zero before. The screenshot artifacts exhibit genuine longer source slider tracks without losing values, dice, locks or step buttons.

But the same audit correctly **FAILED 18 measurements**: `stripeShadowStrength` in all three structures and both themes at each of 791, 850 and 899px had the native stepper extend to x316 while its containing source field ended at x230 (86px outside). The related Lighting slider rows had the same non-stacked inherited rule but were initially disabled, and source fields at 900 and 1024px still rendered tracks at **zero width**. The causes were the old `flex-flow:row nowrap!important` rule on nested Shadow/Lighting range fields and a too-narrow correction breakpoint. No green classification was claimed for this failed run.

## Current remediation and regression coverage

The candidate now wraps original source range rows at **791–1150px**, matching the actual narrow 310px desktop sidebar from `styles.css`. The older nested Shadow and Lighting `!important` row layouts are explicitly overridden **for range fields only**, leaving their choice/dropdown siblings and the special four-column Material rotation geometry unchanged. The existing inline layout remains at 1151px and wider; mobile 790px and below is unaffected. Source control IDs, form values, handlers, locks, randomization and generation/recipe logic are untouched.

`scripts/visual-narrow-desktop-range-agent1.mjs` runs as a **separate parallel job** in `.github/workflows/visual-agent1.yml`, avoiding a dependency on completion of the much larger 416-screen baseline atlas. It records actual DOMRange label ink, source stepper/number/range rectangles, source field/card bounds, button rectangles, die/lock targets, disabled state and controls intersections. Its **13 viewport profiles** include 412, 499, 500, 790, 791, 850, 899, 900, 1024, 1150, 1151, 1280 (all ×892) and 700×412 landscape. It exercises Paths, Radial and nested Regions in **both themes**, saves genuine source-card screenshots and fails for any slider (including disabled controls) with less than 64px of native track inside the affected desktop band, label collisions, child collisions or steppers outside their actual fields.
