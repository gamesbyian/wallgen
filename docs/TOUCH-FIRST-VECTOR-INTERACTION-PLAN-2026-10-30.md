# Touch-first, vector-native interaction system
Owner decision: 30 October 2026. This document owns the interaction overhaul prompted by the completed rotation work. The current queue is still `CURRENT-WORK-QUEUE-2026-10-24.md`; this is an implementation/reference contract, not a competing dispatch.

## Product outcome
Make drawing and editing fast for casual randomize-first work, while allowing deliberate, precise, one-thumb manipulation. All geometry/edit operations use **canonical vector-space values**. CSS pixels are permitted for finger hit targets, pointer displacement, gesture thresholds, preview rasterization and accessibility. Output raster pixels must never become an authored geometry unit by accident. Existing normalized 600×1300 design coordinates and legacy percentage-based controls are valid vector-space conventions; do not create a parallel 0–1 model to replace them merely for aesthetics.

**Pre-release schema freedom (explicit owner instruction):** ROYGBIV is not released. Existing JSON/PNG recipe shapes, names, field groupings, normalizers and public API contracts may be renamed, consolidated, retyped or replaced when evidence shows a materially cleaner or more capable coherent model. Do **not** treat old compatibility or historical renderer pixel equality as architecture blockers. Migrate the app, UI, renderer, worker/headless, MCP, saved favourites/library, metadata, tests and representative existing recipes together when a change warrants it; preserve original imported files, user-created saved designs when reasonably feasible, opt-in consent and source provenance. Document intentional breaking changes and offer a safe import/upgrade or actionable refusal for unsupported old recipes. Avoid maintaining two permanent competing geometry models or broad migrations with no benefit. Invariant: a current canonical recipe describes one reproducible editable composition, not viewport pixels.

## Unified interaction architecture
1. **Three disjoint spaces:** model/design coordinates (persisted geometry), viewport/camera transform (view only), CSS screen coordinates (pointer, touch, hit). One explicit invertible mapping between design and screen for each selected scene layer. No scaling of a historical rendered bitmap used as an inverse hit model. Camera zoom and panning must not mutate the artwork.
2. **Gestures as transactions:** pointerdown records authoritative object ID, starting recipe/model snapshot, original pointer/camera mapping and constraint settings. No authored change until measurable movement. Pointercancel, lost capture, tool switch, lock activation or selection change must roll back; pointerup commits one Undo. Canceled gesture must not leave pending provisional frames.
3. **Direction constraints distinct from snapping:** lock one horizontal/vertical (later diagonal/tangent) movement axis; snap attracts to a *specific valid geometric target*. Screen-distance thresholds and optional hysteresis manage acquire/release; raw unquantized value remains available. Hard constraints must never silently override user-selected one.
4. **Large but unobtrusive touch targets:** control entry/exit reachable at least 44 CSS pixels where used; visually small anchor glyphs can have larger invisible hit regions, with exact-closest anchor priority near crowds and disambiguation for overlaps. Offset handles and selection cycling are conditional follow-ups.
5. **Property-aware precision:** different angular, linear, normalized, multiplicative, opacity, texture-frequency and curve-shape semantics; field descriptors define dimensions, meaningful default range, precision, min/max, wrapping vs clamping, snap targets, lock prerequisites, interactive gain and formatting. Coarse/fine changes must be incremental and never teleport.
6. **One authoritative model:** no separate transform dialect; editable vector points / objects remain identical through UI, recipe JSON, PNG metadata, worker/headless and agent API. Display formatting may round, but should not destructively round canonical values. A semantic field can be stored in a new schema when necessary, without indefinite obsolete aliases.
7. **Provisional rendering:** immediate light preview allowed only within the active gesture token; exact settled raster on commit. Existing rotation proven approach is reusable only after verifying specific new control latency and stale-frame cancellation.
8. **Accessible control states:** names, disabled explanations, pressed/locked state, keyboard numeric alternatives, sensible focus return, reduced motion and no unintended browser panel swipe. On-screen modifier may be temporary or pinned, but must be usable with *one thumb*, not require a second hand.

## Ranked implementation slices
- **V0, accepted in software on PR #866 (30 Oct):** one explicit `Lock axis` tool-state in Edit points; choose dominant CSS-screen direction after 8 CSS px, then restrict normalized point/tangent movement to that axis. No added recipe setting or renderer. Existing path undo, cancel and imported/saved geometry remain authoritative. Code: `src/axis-constrained-drag.js`, `src/draw-path-ui.js`, `tests/axis-constrained-drag.test.js`; repeatable browser proof: `scripts/vector-axis-touch-browser.mjs`. [Quick CI](https://github.com/gamesbyian/wallgen/actions/runs/41016903906) PASS and [one-shot Chromium acceptance](https://github.com/gamesbyian/wallgen/actions/runs/41017280384) PASS with eight 320×700/412×892 cases, including actual save and cancellation, 64×44 entry and no-op pointer. [Evidence artifact](https://github.com/gamesbyian/wallgen/actions/runs/41017280384/artifacts/12959938210). Neither subjective touch comfort nor physical Pixel/IME/TalkBack is asserted.
- **V1, source/browser accepted on PR #870 (integration pending):** Selected node gets a detached screen-space grip of 22 CSS-pixel hit radius / 44px diameter, only when safe from neighboring anchors, tangents, canvas edges and overlapping inspector. Direct original point/handle selection still takes priority. The Draw panel now collapses on entry to Edit points throughout phone portrait (≤599px), retaining the original Show controls entry; reopening recomputes the offset target. [Real Chromium acceptance #41020163872](https://github.com/gamesbyian/wallgen/actions/runs/41020163872): 6/6 offset grip and 8/8 prior axis regression workflows at 320×700 and 412×892; [image/report artifact](https://github.com/gamesbyian/wallgen/actions/runs/41020163872/artifacts/12961685865). Physical touch/tactile judgement unverified. Complex crowded overlap selection cycling and snap-guide visuals remain potential future work only after reproduced need.
- **V2, source audit documented, implementation queued:** [parametric path schema/migration decision](VECTOR-PATH-CANONICAL-MODEL-DECISION-2026-10-30.md). Existing `customPath` is sampled geometry with manual point/corner indices, **not exact parametric Bézier controls**. The proposed normalized-design `M/L/C`-style command graph uses stable authored IDs, explicit closed state and true line/cubic segments. A pure deterministic compiler must feed the current renderer and text-follow pipeline; intentionally migrate all recipe/UI/Undo/worker/agent/import consumers together and retain original source bytes. Only expose four continuity modes once full real vector controls pass acceptance. Do not let historical schema compatibility veto pre-release redesign.
- **V3:** selected objects/text move/scale with proportional and centre scaling; constraints, snaps and screen-space grips. Reuse actual canonical scene identity, selection and 44px targets.
- **V4:** scalar/relative numeric inspectors based on existing rotation scrubber. Unit descriptor and safe expression grammar (e.g. plus, multiply, explicit relative percent where well-defined), not arbitrary `eval`; avoid a second settings schema.
- **V5:** layer cycling and overlap hit-testing; camera pan/pinch/zoom gesture arbitration with invariant artwork. Camera zoom stays 10% increments where controlled by UI.
- **V6:** adaptive preview for complicated geometry/materials only where measured, material/colour controls, comparison and randomize workflow improvements.

## Exit checks for each slice
Prove no-op pointerdown, 44px entry, fast+fine touches where applicable, free versus constrained, change of drag direction, orientation/zoom mapping, locks/prerequisites, Escape/pointercancel, loss of capture, selection identity, one Undo, JSON/PNG roundtrip and no stale preview. Use focused Node tests then proportional Chromium 320×700 and 412×892 journeys with genuine input and inspected images when scene output changes. No fictional physical Pixel/TalkBack/IME proof; hardware and human judgement remain separate. Use lean `npm run check:quick` on ordinary changes, no permanent bloated CI matrix. Reserve true high-resolution optical comparisons for renderer changes.
