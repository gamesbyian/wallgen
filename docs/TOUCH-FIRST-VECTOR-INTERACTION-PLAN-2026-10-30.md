## V3 · Scattered on-canvas gesture transaction ownership (31 October 2026, PR #930)

The existing Move shapes on canvas tool revokes **both** selected-shape move and scale pointer ownership when the object picker changes, even when the canonical recipe stays identical. Browser blur, viewport resize and page visibility loss also discard provisional gestures and release captures *before* any delayed lost-capture event. A recipe incarnation change during source/UI synchronization invalidates both gesture owners, and both pointerup handlers independently check immutable source identity and the selected object index using one shared pure predicate. Invalid/canceled gestures cannot write a source override or Undo entry; valid releases retain the original one-Undo transaction. All this operates on existing normalized vector geometry and portable object overrides, with no CSS-length recipe fields. Required quick tests include source-instance reuse, selection conflicts and lifecycle wiring. **Real two-viewport Chromium [#41250887137](https://github.com/gamesbyian/wallgen/actions/runs/41250887137) PASS** at 320×700 and 412×892: mid-resize and mid-move picker switches, browser blur, viewport resize, unchanged source after interrupted gestures, and a subsequent valid scale with one Undo were all independently exercised. The reusable `tests/scattered-gesture-ownership-browser.mjs` remains; one-shot workflow must be retired before integration. Physical Pixel and TalkBack remain untested.



## V3 · Fixed-opposite-edge proportional shape resizing (31 October 2026, merged #927)

Existing on-canvas scattered **Move shapes** tool now offers a separate 44-CSS-pixel **Scale from edge** switch (off by default), independent of centre snapping and direction locking. This implements the research-backed alternate transform origin without a second scene graph, saved CSS pixel dimensions or a new recipe property. The control holds the *opposite actual bound edge* fixed under uniform scaling. For imported compound silhouettes, the pivot is obtained from the same original authored polygon rings and placement used by `scatteredSelectionBounds`, including disconnected islands and holes; circles retain exact analytic extents. The center and radius both update through the original `scatteredMoveOverride` normalized source writer. Screen-grip movement measures scale from the fixed edge to the detached real grip, with bounded clamping and one Undo on actual pointerup. Keyboard size commands honor the same pivot. The switch is captured once at pointerdown; lost capture, Escape, tool exit, intervening recipe edits and no-op drags retain their existing refusal paths. **Both centre and edge scaling require 8 CSS pixels of intent before recording a resize**, preventing accidental tiny finger jitter. Real two-size Chromium [#41250340269](https://github.com/gamesbyian/wallgen/actions/runs/41250340269) **PASS** at 320×700 and 412×892: each 44 CSS-pixel Axis/Snap/Pivot/Done target was unobstructed, an anchored enlargement preserved the exact opposite left boundary (x=132 authored units), default centre enlargement retained x=180, keyboard edge resize preserved the boundary, micro-jitter made no edit, and every change was independently undoable. The resize grip follows the pointer during preview so a changing selection outline cannot strand the release event; this is editor CSS only. The old centre scaling is unchanged by default. During a live resize, the disposable 44px grip follows the actual finger to avoid losing a pointerup when the vector selection bounds move under it. Focused pure regression cases and source wiring checks are permanently in `tests/scattered-scale-gesture.test.js` (required quick suite). **[PR #927](https://github.com/gamesbyian/wallgen/pull/927) merged at `99aae523`; final cleaned-head [quick CI #41250419103](https://github.com/gamesbyian/wallgen/actions/runs/41250419103) PASS.** Chromium pointer and keyboard acceptance passed for the stated cases; physical Pixel and TalkBack remain unverified independent acceptance gates.

## V3 · Text-anchor magnetic alignment (31 October 2026, merged #917)

The existing opt-in **Move text on wallpaper** mode gains a separate 44 CSS-pixel **Snap anchors** toggle, initially off. It reuses the shared `snapVectorNode` 8 CSS-pixel acquisition / 14 CSS-pixel release hysteresis already used by Bézier nodes and scattered shapes. Guides come from the original canonical anchors of *other visibly painted text overlays* (including locked text) and the finished wallpaper centre, excluding disabled, transparent and inkless text. Snap happens after the existing one-thumb direction acquisition; only the moving axis can magnetically align. On pointerdown, both toggle state and guide history are frozen for that gesture. All results flow through the existing canonical `dragTextOverlay` writer, source-identity refusal, pointercancel/lostcapture handling and one-step Undo. The finished-artwork coordinate mapping uses actual CSS canvas width and height; camera position and preview pixel count do not become text coordinates. Output raster pixels must never become an authored geometry unit by accident. Existing normalized 600×1300 design coordinates and legacy percentage-based controls are valid vector-space conventions; do not create a parallel 0–1 model to replace them merely for aesthetics.

## Unified interaction architecture
1. **Three disjoint spaces:** model/design coordinates (persisted geometry), viewport/camera transform (view only), CSS screen coordinates (pointer, touch, hit). One explicit invertible mapping between design and screen for each selected scene layer. No scaling of a historical rendered bitmap used as an inverse hit model. Camera zoom and panning must not mutate the artwork.
2. **Gestures as transactions:** pointerdown records authoritative object ID, starting recipe/model snapshot, original pointer/camera mapping and constraint settings. No authored change until measurable movement. Pointercancel, lost capture, tool switch, lock activation or selection change must roll back; pointerup commits one Undo. Canceled gesture must not leave pending provisional frames.
3. **Direction constraints distinct from snapping:** lock one horizontal/vertical (later diagonal/tangent) movement axis; snap attracts to a *specific valid geometric target*. Screen-distance thresholds and optional hysteresis manage acquire/release; raw unquantized value remains available. Hard constraints must never silently override user-selected one.
4. **Large but unobtrusive touch targets:** control entry/exit reachable at least 44 CSS pixels where used; visually small anchor glyphs can have larger invisible hit regions, with exact-closest anchor priority near crowds and disambiguation for overlaps. Offset handles and selection cycling are conditional follow-ups.
5. **Property-aware precision:** different angular, linear, normalized, multiplicative, opacity, texture-frequency and curve-shape semantics; field descriptors define dimensions, meaningful default range, precision, min/max, wrapping vs clamping, snap targets, lock prerequisites, interactive gain and formatting. Coarse/fine changes must be incremental and never teleport.
6. **One authoritative model:** no separate transform dialect; editable vector points / objects remain identical through UI, recipe JSON, PNG metadata, worker/headless and agent API. Display formatting may round, but should not destructively round canonical values. A semantic field can be stored in a new schema when necessary, without indefinite obsolete aliases.
7. **Provisional rendering:** immediate light preview allowed only within the active gesture token; exact settled raster on commit. Existing rotation proven approach is reusable only after verifying specific new control latency and stale-frame cancellation.
8. **Accessible control states:** names, disabled explanations, pressed/locked state, keyboard numeric alternatives, sensible focus return, reduced motion and no unintended browser panel swipe. On-screen modifier may be temporary or pinned, but must be usable with *one thumb*, not require a second hand.
