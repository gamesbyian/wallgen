# Text overlays and typography: product specification and implementation queue

## Agent 2 T3f: trustworthy Unicode coverage for actual custom faces · 24 October 2026

**[PR #681](https://github.com/gamesbyian/wallgen/pull/681), isolated from reconstruction:** a natively loadable TTF/OTF does not necessarily contain every authored glyph. A browser may substitute a default/system font for missing Arabic, CJK, emoji or combining marks, making the advertised selected typeface appear more capable than its actual binary. A pure, bounded OpenType SFNT cmap reader (formats 4 and 12) is now called only **after** the current integrity and native FontFace.load checks of curated or private fonts. It caches compact character-coverage lookups in memory keyed by existing IDs; it does not change canonical recipes, serialize glyph inventories, store private bytes, request new URLs or block browser fallback. The selected Text object displays an exact missing-codepoint warning, with async stale-selection suppression and no per-keystroke forced focus changes. System preset fonts have OS-dependent glyph fallback and deliberately do not claim exact coverage.

**Technical proof:** real Node source test includes hostile/truncated tables, indirect glyph-array format 4, supplementary-plane format 12, unique missing Unicode codepoints, and actual cmap parsing of **all 27 vendored OFL TTF binaries**; [quick run #40158114120](https://github.com/gamesbyian/wallgen/actions/runs/40158114120) **PASS** on rebased current main, including the complete indirect-glyph and unknown-cmap tests. Actual [Chromium source/browser run #40157754029](https://github.com/gamesbyian/wallgen/actions/runs/40157754029) **PASS** at 412×892 emulated portrait: native Bangers selection and a genuine private Bangers TTF import each correctly identify the exact same **six missing codepoints** in "HELLO 𠮷 مرحبا" (U+0627, U+0628, U+062D, U+0631, U+0645, U+20BB7). Supported Latin "HELLO" correctly clears the warning; switching to system preset clears it; embedded recipe preserves text and SHA-derived private font ID, not original font name. Actual source direct versus fresh worker 360×780 **0 differing pixel channels**, PNG 265,565 bytes, zero page exceptions. Normal app startup fetched its **pre-existing** Fredoka/Rubik UI webfonts from Google Fonts; only those known origins were observed, with **no authored text** in request URLs. This does not constitute zero remote traffic from the whole application, nor physical Android/privacy penetration testing.

**Limits:** cmap existence verifies *codepoint mapping*, not OpenType GSUB ligatures, mark positioning, native colour-emoji support, variable axes, identical font selection across OSes, or actual glyph artistic quality. Unknown cmap formats produce an explicit UNKNOWN status, never a definitive missing-glyph verdict. Actual target-device Chrome/IME/TalkBack/thermal tests remain Agent 3/human scope. Independent user-font redistribution rights are unchanged; no font binary enters regular PNG/JSON transport. Final actual-current-source [Chromium #40158114118](https://github.com/gamesbyian/wallgen/actions/runs/40158114118) **PASS** on merged-main-based head: bundled/private warnings identical, real worker output channel differences **0**, six missing codepoints, no authored text in network URLs, and mobile presentation measured **342px width, no overflow** at 412×892 and **250px width, no overflow** at 320×700. Browser screenshot of the actual narrow warning was directly inspected. The long-lived cmap4 cache copies only bounded glyph IDs rather than retaining original private font ArrayBuffers, and short-lived workers skip this UI-only parser; this is source-supported storage discipline, not a measured heap profile. The one-shot browser workflow was **retired after successful pixel review**; the manual proof script remains. Issue #653 stays open for those external and shaping gaps.

## Agent 2 T3e: opt-in expressive ink and curve layout · 24 October 2026

**[PR #672](https://github.com/gamesbyian/wallgen/pull/672), stacked behind #669:** introduces optional canonical `letterSpacing`, `lineSpacing`, `rainbowOffset`, `rainbowReverse`, and `shadow` / blur / distance fields without changing old recipe defaults. Straight runs use the browser's native Canvas letter-spacing operation, retaining whole-line RTL/ligature shaping. Curved lettering uses the same attributes inside its existing glyph painter. Optional black/white shadows are rendered from the text fill once (strokes do not double-cast them), with blur/offset scaled for the export resolution. Rainbow phase/reversal derive from the actual seven-colour scene, not an independent stripe engine. Direct hit bounds account for tracking and leading. The extra controls sit inside a collapsed Text-options subgroup, with irrelevant shadow/rainbow controls disabled until active.

**Visual correction discovered during artwork inspection:** multiline lettering on steep Wave/Arch paths initially used a fixed screen-Y offset, letting adjacent lines cross when their baseline tangents tilted. The renderer now offsets each glyph along its **local curve normal**, preserving authored line leading perpendicular to the stroke. A geometric regression guards this; physical creator evaluation is still required for dense loop/hairpin text.

**Proven baseline before normal-offset correction:** [actual Chromium #40141538010](https://github.com/gamesbyian/wallgen/actions/runs/40141538010) **PASS** for nine reference wallpapers, 9/9 direct vs fresh-worker **0 differing pixel channels**, real 3024×6552 shadowed PNG decoded (2,084,407 bytes), browser errors **0**. Explicit styled-versus-neutral difference was **88,737 channels** for tracked/rainbow/shadow Wave text and **33,020 channels** for intact native-shaped Arabic shadow text. [Focused Node quick CI #40141661409](https://github.com/gamesbyian/wallgen/actions/runs/40141661409) **PASS** including the perpendicular offset regression. The **post-correction**, visually inspected [source-art run #40141783438](https://github.com/gamesbyian/wallgen/actions/runs/40141783438) also **PASS**: all **nine** current-renderer wallpapers matched fresh worker PNGs channel-for-channel (0 differences), 3024×6552 shadow export decoded (**2,084,407 bytes**), and no browser errors. The new true two-line Wave sample changed **69,750** channels versus no lettering and **84,365** channels versus the same unstyled text, while the intact Arabic effect changed **33,020** versus unstyled. The perpendicular-offset correction reduces incorrect crossing on sloping baselines; very tight/high-curvature multiline turns can still crowd and require author size/leading adjustments. One-shot screenshot CI was removed from the branch after source inspection.

**Still open under #653:** arbitrary curved placement of contextual joined/bidi glyph clusters (native shaping currently retained straight), advanced multi-stroke layering and directional shadow options, accurate glyph-ink picking, private-TTF plus full-resolution curved-shadow combined stress, real Android IME/TalkBack/touch and thermal/memory verification. There is no proven guarantee of Canvas `letterSpacing` support on older browser engines; native fallback leaves the text whole, rather than using incorrect per-character shaping.

## Creator outcome
Place and edit one or more phrases directly on a finished ROYGBIV wallpaper without switching apps. Type once, change appearance rapidly, export with correct fonts and outlines. Written words are always protected against ordinary randomization. No eighth top-level category: **Details → Text** owns the object list and controls.

## Committed semantics
- Typography is authored first-class **canonical recipe data** (bounded `textOverlays` array), normalized by `src/model.js`, previewed by `src/renderer.js`, exported through the existing worker/headless/reference paths and encoded by the existing PNG metadata/JSON/share machinery. No DOM-only paint on top of a preview, no separate art model.
- Initial stack order: each text object above completed composited rainbow, material, lighting and Photo; no ambiguity with stripe shadow, camera nudge cache or metadata. The text position uses percentages of the **final wallpaper frame**; type size uses 600×1300 canonical design units. Rotation occurs about each text anchor. Nudge moves the rainbow beneath anchored lettering. The existing view camera reframes base artwork, not the lettering. This is intentional and should be exposed to users.
- Styles: black/white fill, sequential ROYGBIV colour per grapheme or per word (spaces don't increment the colour), and continuous horizontal seven-stop rainbow gradient. Use the active canonical palette/stripe hue ordering; reversal is reflected. All colour modes permit none/black/white exterior stroke with adjustable thickness. Wrap text only at authored line breaks; shrink overlong lines conservatively to fit the frame; cap objects, lines and code points.
- Editing operations use existing `changeRecipe`/Undo path; restore via saved recipes, PNG metadata and clipboard. Removal is explicit. Accessible HTML textarea/select/range controls inside a seven-category card; no forced IME dismissal, no live focus jump per keystroke.
- Preset typefaces must be robust to worker rendering and export. First foundation uses common system fallbacks, with honest device variability. Named new/bundled licensed fonts need visual proof of actual final glyph availability rather than CSS family strings alone.
- Randomize never changes `text` content. Scoped typography randomization may change visual style, position, outline and transforms of **unlocked** text objects; per-object lock protects that object. Global randomize must preserve all authored text objects by default, including their style until an explicit text reroll is chosen.
- Typography must remain opt-in, default recipes show no text. No text is uploaded. Existing voluntary creative telemetry policy remains unchanged.
