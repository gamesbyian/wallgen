## Implementation and coordination invariants

1. **Safeguard existing recipes first.** Keep every old saved authoring choice and old image mode unchanged unless the user explicitly approves a new meaning. Add a named opt-in style/field when necessary. Test exact save/load/Undo/worker/PNG round-trips and source controls for the changed feature. A source-normalized v2 recipe is not automatically semantically equal to an image made by an earlier generator.
2. **Meet the user's actual artistic goal.** Seven distinguishable stripes/colour identities remain, although a specific authored composition may intentionally overlap. Preserve the 210% native export target. The generator is used predominantly on a phone in portrait; Edit pane should fit without vertical scrolling. Randomize respects per-setting locks. Avoid sprawling tabs, duplicate inspector tools, or meaningless disabled controls.
3. **Default to lean CI.** `npm run check:quick` is the only normal PR gate (including focused authentic-v1 integrity since #525), with **no browser install or screenshot generator**. `npm run check` is opt-in for a relevant broad change. One-off Chromium review may be branch-gated, but restore `.github/workflows/check.yml` **byte-for-byte before merge**, check CI and leave zero temporary jobs. Use existing `scripts/review-*.mjs` tools before building new infrastructure.
4. **Distinguish four evidence levels:** implemented source; deterministic Node test; actual exported PNGs opened, validated and visually judged; actual physical handset interaction/performance. Report each truthfully. Archived GitHub Actions artifacts expire, while source recipes, manifests and finding documents should remain in the repo.
5. **Write as parallel agents.** First check live main/open PRs and avoid overlapping branches that both edit `index.html`, `src/app.js` or canonical roadmap. Keep individual source PRs focused; update the relevant plan, issue and *this handoff* once work lands. Do not use a historical open PR or work-lane note as proof someone is actively editing.
6. **Handoff quality bar:** no unmerged useful implementation, no temporary CI code, no fabricated physical approvals, and each still-open issue has a verifiable next action. Source of truth is **GitHub main**, not the status of this chat, disconnected vaults or old roadmap paragraphs.
