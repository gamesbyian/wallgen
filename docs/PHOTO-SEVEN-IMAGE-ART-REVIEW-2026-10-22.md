# Seven-image Photo finishing art review (manual)

**First actual review completed on 2026-10-22.** The seven-image Chromium run succeeded in [Actions #39819624080](https://github.com/gamesbyian/wallgen/actions/runs/39819624080). The exact production PNGs were downloaded, inspected visually side by side, and checked for complete image CRC and matching embedded recipes. See the [observed photographic treatment review](PHOTO-PRODUCTION-RENDER-FINDINGS-2026-10-22.md) for concrete results. The original opt-in script below remains reusable. Do not confuse **this completed first art review** with pending physical-device validation, composite materials/threads or actual film-stock emulation.


**Purpose:** Judge what the actual ROYGBIV Photo presets *look like*, using the production renderer, instead of treating green unit tests or mathematical source properties as proof of aesthetic quality. This is a **manual, opt-in** contact gallery, not a CI gate or screenshot factory. The existence of the script is not evidence that its PNGs have been rendered or observed.

Run from a full local checkout with Playwright and Chromium available, as required by [the existing headless renderer](../scripts/render-headless.mjs):

```sh
node scripts/review-photo-looks.mjs --out-dir artifacts/photo-review
# Optional: --seed photo-review-002 --browser /usr/bin/chromium
```

The script generates **exactly seven** 600×1300 metadata-bearing ROYGBIV PNGs, matching `.recipe.json` files, a `manifest.json` with source recipes and an `index.html` contact gallery. All wallpapers share one seed and a deliberately simple black-background seven-colour diagonal composition, with the same geometry, material, camera and lighting. The untreated source is followed by six isolated/representative looks: Slide Film, Muted Negative Print, Film Grain Only, Warm Film Halation Only, Smartphone HDR Inspired and Low-resolution Webcam Capture.

Every file is generated by `scripts/render-headless.mjs --recipe <exact normalized JSON>`. The script does **not** reconstruct source state with command-line `--set` flags, so the gallery, PNG and manifest cannot silently disagree on the art recipe. Output dimensions are a small production-rendered 600×1300 representation, not a 19.8 MP performance test. Use a new output directory for each review; the script refuses to overwrite any existing contact image or manifest.

## What to judge from actual images

- **Untreated original:** Are yellow/green edges genuinely luminous against black? Does the base give the new looks something meaningful to change?
- **Slide vs muted negative:** Are the two film profiles distinguishable beyond generic saturation? Are blacks and rainbow colour relationships appealing?
- **Grain-only:** Does grain look usefully fine rather than like a coarse repeated grid? Are hue, contrast and vignette otherwise unchanged as specified?
- **Halation-only:** Does red-orange light appear *outside* luminous stripe edges and fade naturally? Is there red tint inside the stripe, on unrelated objects or far from any bright edge?
- **Smartphone HDR:** Are shadows lifted appropriately without making black backgrounds grey or clobbering saturated hue identity?
- **Webcam capture:** Are reduced detail/chroma bandwidth legible, with reasonable sampling/blocking rather than an arbitrary tint? How do small and large output dimensions compare?
- **Composition/combined effects:** Does the final Photo pass respect the authored camera frame, regions, threads and independent material layers? This particular simple study does not certify complex compositions, saved-file import, actual phone interaction or full-size export.

Record `actually generated`, `actually viewed`, and any **specific observed defect** separately. Do not interpret test-passing scripts as an artistic signoff. Only expand to one complex stitched/material composition or a full-size Pixel 6 Pro file if the seven simple pictures expose a relevant defect or memory concern.
