## Product and engineering priorities

ROYGBIV is a free, mobile-first, **portrait Pixel 6 Pro Chrome/PWA** wallpaper studio; the owner normally explores through randomization, then locks, edits, compares and exports. The editor is one-screen/canvas-first, keeps seven category concepts, and must deliver actual editable compositions, not menu mockups. A specialist result must work through **current canonical recipes and scenes, editor/locks/randomize/Undo, direct/worker/headless rendering, visible PNG/JSON export and metadata transport** as applicable.

**Owner priority:** improve the *current* recipe and rendering experience over reproducing past generation pixels. Historical recipe compatibility is a **nice-to-have**, not a shipping gate. Original uploaded/source PNG bytes, privacy, provenance, honest unsupported-image refusals and explicit user intent are **always** protected. Actual visual quality needs viewed ROYGBIV artwork, not only source reasoning or numerical scores.

## Shared engine: non-negotiable integration rules

- `src/model.js` is the owner of `normalizeRecipe`, `resolveScene`, current canonical settings, locks, seeds and effective state. Before coding, search the real reusable geometry/composition/portable-shape, font, image import, photo, surface, state transaction, camera and render modules. **No forked renderer, duplicate asset picker, shadow recipe dialect or hidden second Undo system.**
- Reuse genuinely shared semantics but preserve deliberate math differences (palette, displacement, noise, embroidery, topology). Abstraction for its own sake is not an improvement.
- New meaningful settings propagate through **editor UI → canonical state → scoped randomization/locks → Undo/history → rendered preview → worker/headless/export → PNG/JSON transport**. Camera framing is intentionally independent of artwork regeneration.
- Image reconstruction creates *possible present-day editable recipes* from measured source pixels, never recovered original authorship/seed or invisible painter order. Preserve originals and show uncertainty; a false-colour candidate is worse than a clear accessible refusal and manual import route.
- Respect current renderer contracts including **normal maximum 6 initial + 10 refinement painters** for inverse fitting, precise image/export geometry, grapheme/font privacy and recorder off-by-default status. If evidence supports intentionally changing one, document the reason and show controlled effects.
- Do not engineer historical backwards compatibility ahead of present-day artistic quality. Protect known current invariants and source preservation, not an ever-growing graveyard of old pixel snapshots.

## Agent protocol

1. **Recover reality:** inspect latest `main`, open GitHub issues/PRs, applicable owner issue/plan and module tests. Reconcile newly merged functionality before creating work; note conflicts and branch leases. Never overwrite Agents 1/2 shared `src/app.js`, `index.html`, `src/model.js` or common docs from a stale checkout.
2. **Pick a falsifiable useful result:** name current defect, owner-visible effect, minimal reproduction, module authority and measurable acceptance. Prefer a small complete real user journey over another speculative research programme. If there is no evidenced defect, mark the limitation and stop creating speculative fixes.
3. **Implement and validate proportionately:** `npm run check:quick` plus tests nearest the change. For art, **inspect actual renderer PNGs** (before/after with same conditions). For phone UX, use genuine browser route and meaningful controls; inspect visible exported PNG, focus, Undo and pointer effects as relevant. Add one-shot heavy runs only for a demonstrated gap, retire automatic heavy PR triggers before integration. Do not rebuild recurring release-grade CI.
4. **Maintain honest evidence tiers:** distinguish source-only / deterministic Node / real Chromium emulated portrait / actual viewed PNG / physical Pixel 6 Pro or native Android IME/TalkBack / genuine human use / authenticated remote backup. Never upgrade a lower tier by rhetoric. Real hardware, thermal, human aesthetics and private remote backup remain **unverified until independently performed**.
5. **Protect privacy and intellectual provenance:** recorder and surveys default **off**; GitHub backup to the existing private `gamesbyian/general-purpose:data/roygbiv-usage` is separately opt-in. Do not include keys/fonts/private image data in public commits. No human-study fabrication, covert session recording or fake uploaded conversation transcripts. Historical conversation extracts in `prod_diary` are **partial**, not full-chat exports.
6. **Land or clearly hand off:** focused branch and PR, green relevant quick CI, qualification for merge, then refresh `main`/open PRs/issues. Fix only necessary current entry points. Put the concise new result, exact source SHA and next action in the live queue/owner issue when the status actually changes; keep detailed evidence in one owning plan/report, **not copied into five status documents**. Close a completed issue with evidence, not with an invented physical acceptance claim.
